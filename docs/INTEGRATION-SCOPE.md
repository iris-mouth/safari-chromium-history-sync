# 統合製品の初期仕様

Q1〜Q31の回答と、2026-11-13のQ32への「OK」により確定した初期仕様。新機能の実装・実機検証はこれからであり、この文書は達成済みの結果を示さない。

## 目的と初期範囲

safari-chromium-history-syncの既存ブラウザ間同期に、元ブラウザの履歴を閲覧用DBへ取り込む機能と、HistorySyncWeb由来のWeb閲覧を統合する。このMacと、本人のTailscaleアカウントで接続するiPhone・PCで利用する。

- Safariは現在の同期が使う標準の履歴DB1つ。Chrome/Edgeは明示的に選ぶプロファイルを扱う。
- 同期相手は既存の単一プロファイル。保存対象は別に複数選べる。
- 旧HistorySyncのDB・設定・アイコンキャッシュは移行せず、ブラウザに現在残る履歴から始める。
- 収集・Reader/APIはSwift、Web画面はReact。Python/Node.jsを実行時依存にしない。

## 収集する履歴とブラウザとの関係

元DBのHTTP/HTTPS訪問を1件ずつ扱う。同じURLの複数訪問を集約せず、ブラウザ画面側の重複整理・省略も再現しない。収集元と元の訪問の識別情報・時刻精度を保持し、同じ訪問を再取得しても重複させない。別のブラウザ・プロファイルの記録は別に残す。

Sync Assistの補助URL、疎通テストURL、製品のWeb閲覧画面URLは収集対象外にする。一般のexample.com等の閲覧を巻き込まない。内部ページ・ローカルファイルは初期対象外。

- 新しい履歴は、Mac稼働中・取り込み有効・元DBを読める通常運用で、MacのブラウザDBへの到着から1分以内に反映する目標。
- 削除・期限切れは正常な照合で確認し、通常運用で5分以内の反映を目標とする。同じURLの昨日分だけが消えたら、統合DBの対応する昨日分だけを削除する。
- 他の日時や他の収集元に残る記録は保持する。照合のために原本ブラウザを書き換えない。
- 読取失敗や未完了を削除とみなさず、最後の正常な結果・失敗元・最終成功時刻を示す。読める収集元の取り込みは続ける。
- 同じ保存対象の元DBが再作成・置換された場合は、その収集元だけ全件再取得し、正常完了後に反映する。
- 保存対象から外した収集元のデータは統合DBから取り除く。再選択時は元ブラウザに残る分を再取得する。

訪問時刻と取り込み時刻を区別する。元ブラウザが保持していない個々の過去タイトルや訪問元端末は推測しない。

## 閲覧と状態表示

履歴一覧・検索はMacでもWebを使い、Macの画面は設定・状態表示・Webを開く操作に絞る。初回取り込み中も保存済みの部分から閲覧でき、初回収集中・保存件数・未完了・取得完了で0件を区別する。

現在のWebの次の振る舞いを引き継ぐ。

- 日付・開始日と終了日を含む期間表示、前日・翌日・今日への移動。共通タイムゾーンはAsia/Tokyo。
- 初回は最新の履歴日、全体0件なら今日を表示。訪問日時・ローカルアイコン・タイトル・サイトを密に並べる。
- 全期間のタイトル・URLを、NFKC・casefold・かな変換で正規化して空白区切りANDの部分一致検索。記号を演算子にしない。
- 入力停止300msで検索、IME確定待ち、Enter即実行、古い応答による上書き防止。
- 初期200件、100・200・500件の選択と「さらに読み込む」。必要なページだけを取得する。
- 詳細と元URLを開く操作、ブラウザの戻る・進むで条件と位置の復元。対象行が消えた場合は残る近隣へ寄せる。
- 表示中の行は自動で並べ替えず、条件変更・再読み込み・追加取得で現在のDBを確認する。
- アイコンはブラウザから取得できるローカルデータを使い、欠損時は代替表示。サイトや外部アイコンサービスへ問い合わせない。
- キャッチコピー、「この日の前後を見る」、製品内の非表示・ユーザー収集除外・手動削除は提供しない。

Macのメニュー・ダイアログは既存の英語方針、Webは現在の日本語文言を基準とする。元データのタイトルやプロファイル名は元の文字列を使う。

## 責務と起動・停止

| 部分 | 責務 |
| --- | --- |
| Agent | FDAを持ち、既存ブラウザ間同期と、独立した収集・照合・統合DBへの書き込みを担当 |
| Viewer | FDAと同期用秘密鍵を持たない別プロセス。統合DBを読み取り専用で参照し、APIとWeb画面を配信 |
| Menu | 保存対象や停止状態の設定、状態確認、Webを開く操作、製品サービスの起動・終了 |
| Tailscale Serve | localhostのViewerを本人アカウント向けHTTPSで中継 |

ブラウザ間同期、取り込み、Web閲覧のON/OFFは別に扱う。同期停止中も取り込みと閲覧は続けられ、取り込みを再開すれば元ブラウザに残る履歴を補う。設定完了後はログイン時に前回設定で起動する。

メニューアプリ終了時には製品の同期・取り込み・Viewerも終了し、独立したKeepAliveや拡張から勝手に起動しない。ウィンドウだけ閉じることはアプリ終了と区別する。拡張の未送信状態は保持し、次回起動時に元履歴を確認して再開する。

Safari起動・Sync Assistの既存条件を維持する。iPhoneからMacへの受信だけが滞っている場合の追加の自動起動ルールは設けない。反映時間の目標は、iPhoneでの訪問時刻や削除操作からではなく、Macの元DBに変化が届いてからのもの。

統合DB・アイコンは通常SQLiteで保存し、本人に限定したファイルアクセス権で扱う。同期stateの暗号化・Keychain rootの境界は維持する。Webは本人Tailscaleアカウントに限定し、DB本体・設定・秘密を配信対象にしない。

## 初期版に含めないもの

- 旧HistorySyncデータ・設定の移行、別世代保存・バックアップ。
- 非表示、任意の収集除外、製品内の履歴削除、ブラウザ間の削除伝播。
- 複数Safariプロファイル、他OSや追加ブラウザの対応。
- 統計、WebDAV、ブックマーク・メモ、高度な検索DSLなど。

## 完成条件と検証

以下は実装で満たす条件。検証済みを意味しない。

1. 架空のSafari/Chromium DBで、訪問単位・元精度の時刻・同URLの繰返し・同時刻・遅着・再取得の重複防止を検証する。
2. 昨日分だけの削除・期限切れ、取得失敗・中断・元DB置換・保存対象解除を検証し、正常な照合が完了した範囲だけ反映する。
3. 新規1分・削除5分の目標を、Mac到着を起点として条件を記録して測定する。初回の大量取得と通常運用を区別する。
4. 現行UI/APIの振る舞い、正規化検索の一致、IME・応答逆転・追加取得・戻ると位置復元を受け入れ試験で確認する。
5. 現行Webの性能目標を引き継ぎ、架空10万件・iPhone Safari・Tailscale経由で日別1秒以内、入力停止から検索先頭表示は300ms待機を含め2秒以内を目標にする。100万件では劣化を測定する。端末・ネットワーク・キャッシュ条件を記録する。
6. FDA/読み取り専用/本人限定の境界、初回部分表示、収集元別の障害分離、ログイン起動・個別停止・メニュー終了・再開を検証する。
7. 既存のブラウザ間同期・配送証拠・再試行・互換性・クラッシュ回復の保証を維持する。新しい収集用の処理で同期カーソルを巻き戻したり、過去履歴を配送したりしない。
8. コピーDB・架空データでの確認後にこのMacとiPhoneで検証する。現在のViewerからの切替は、新構成の確認後に行い、旧Viewerの独立常駐と新しい終了方針が衝突しないようにする。

HTTPライブラリ、具体的なDBテーブルや索引、分割処理等の実装詳細は、この境界と完成条件に沿って具体化する。
