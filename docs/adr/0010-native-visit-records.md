# 元ブラウザの訪問記録を1件ずつ取り込む

ユーザーのQ23「収集の粒度も元ブラウザ側に合わせます」により、Q1の旧HistorySync同様のURL集約方式を見直す。元ブラウザのDBに別の訪問記録があれば、同じURLでも新製品では別の履歴レコードとして取り込む。

収集回ごとの代表行では、昨日分だけの削除や一部訪問の期限切れを正確に対応させにくい。元の訪問記録を単位とし、収集元・元DBの同一性・ネイティブ訪問ID・元の時刻精度を保って、再取得の重複と削除の対応を管理する。

Q28により、元DBのHTTP/HTTPS訪問を対象とし、ブラウザ画面側の重複整理・省略は再現しない。内部ページ・ローカルファイルは初期対象外とし、Q26の製品専用URLを除外する。元ブラウザが保持していない個々の過去タイトルや訪問元端末は推測しない。
