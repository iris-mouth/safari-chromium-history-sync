# 履歴データの保存時暗号化を追加しない

ユーザーのQ7「旧historysyncの方式に合わせる」に従い、閲覧用の履歴やアイコンを保存する場合は、旧HistorySyncと同じ通常SQLiteを用い、DB自体の暗号化を追加しない。旧実装は標準sqlite3でURL/titleと画像を保存しており、GUIの画面ロックや資格情報の保管はDB暗号化ではない。

保存時暗号化を採用する案と比べ、履歴保存用の鍵配布・復号・鍵紛失時の復旧を初期製品へ追加しない。保存領域は本人に限定したアクセス権で扱い、Web公開範囲は現在の本人Tailscaleアカウントを基準とする。

既存の同期stateの暗号化とKeychain rootの扱いは維持する。保持方針はQ18により見直し、元ブラウザの履歴との一致を目指す。別の世代保存やバックアップを作らない判断は維持する。
