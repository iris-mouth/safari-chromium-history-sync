# 履歴の管理元をブラウザとする

Q16〜Q18により、非表示・ユーザー設定の収集除外・製品内の手動削除を実装せず、履歴の削除は各ブラウザ側で行う。ユーザーの「なるべくdbとブラウザ側の履歴を一致させたい」に沿って、閲覧用の統合DBを元ブラウザの履歴へ近づける方向を採用する。Q23・Q24により、元ブラウザの訪問記録単位で取り込み、昨日分だけ消えたら統合DBの対応する昨日分だけ削除する。通常運用で正常に照合できる条件で、削除・期限切れは5分以内の反映を目標とする。

旧ADR-0004の、元ブラウザから消えた履歴も独立して蓄積し続ける方針を見直す。収集元ごとの記録を区別し、閲覧用DBの照合と既存のブラウザ間配送を分ける。ブラウザ間の削除同期を追加する判断ではない。

取得失敗や未完了を削除とみなさず、正常に確認できた差分を反映する設計にする。Q15の、保存済み履歴の閲覧と読める収集元の取り込みを続ける方針は維持する。別世代保存やバックアップは作らない。

Q19・Q26により、Sync Assist・疎通テスト・製品のWeb閲覧画面URLを固定で除外する。ユーザーが任意の非表示・除外ルールを設定する機能とは分ける。

Q29により、同じ保存対象の履歴DBの再作成・置換を確認した場合は、その収集元だけ全件再取得し、正常完了後に反映する。途中失敗では前回正常分を維持し、未完了の結果で削除を確定しない。同期Writerの互換性・安全性検証と回復操作は維持する。
